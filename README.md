# qath API

Open standard for verified, privacy-preserving road freight movement data.

qath accepts a deliberately small movement record: a vehicle moved from one geographic location to another, over a verified distance, either with or without cargo.

## Core principle

**One record equals one verified movement.**

A movement must represent an actual vehicle movement. Planned, cancelled, estimated, or otherwise unverified movements must not be submitted.

A single movement has one constant cargo state. If the cargo state changes, a new movement starts.

Once accepted by qath, a movement is immutable.

## Movement

A client submits:

```json
{
  "started_at": "2026-09-29T06:12:00Z",
  "ended_at": "2026-09-29T08:04:00Z",
  "origin": {
    "latitude": 52.6612,
    "longitude": 6.7418
  },
  "destination": {
    "latitude": 52.6424,
    "longitude": 6.6219
  },
  "distance_km": 40,
  "has_cargo": false
}
```

qath creates the movement identifier after the movement has been accepted:

```json
{
  "movement_id": "45612368-bd12-44f0-a523-4b530ed8e2f1"
}
```

### Fields

| Field                   | Type          | Meaning                                                                                                 |
| ----------------------- | ------------- | ------------------------------------------------------------------------------------------------------- |
| `started_at`            | UTC timestamp | Actual start time of the movement.                                                                      |
| `ended_at`              | UTC timestamp | Actual end time of the movement.                                                                        |
| `origin.latitude`       | number        | Latitude of the actual movement origin.                                                                 |
| `origin.longitude`      | number        | Longitude of the actual movement origin.                                                                |
| `destination.latitude`  | number        | Latitude of the actual movement destination.                                                            |
| `destination.longitude` | number        | Longitude of the actual movement destination.                                                           |
| `distance_km`           | integer       | Actual driven distance, rounded to whole kilometres.                                                    |
| `has_cargo`             | boolean       | `true` when cargo is being transported; `false` for a truck without a trailer or with an empty trailer. |

## Movement identity

Clients do not provide a movement identifier.

After a valid movement is accepted, qath generates a unique `movement_id` and returns it in the response.

A verified movement represents a historical fact and cannot be modified after creation. The API therefore does not provide update endpoints for movements.

## Idempotency

Every request to `POST /movements` must include an `Idempotency-Key` header.

The key is generated by the client and must remain the same when retrying the same movement submission.

Example:

```http
Idempotency-Key: 7d89a3b4-8b1d-48b7-883c-bad7b2a80550
```

The `Idempotency-Key` is not the movement identifier. It only identifies the submission attempt and makes retries safe.

- First request with a new key: qath creates the movement and returns `201 Created`.
- Same key with the same payload: qath returns the original `movement_id` with `200 OK`.
- Same key with a different payload: qath returns `409 Conflict`.

Clients must reuse the same `Idempotency-Key` when retrying a request whose outcome is unknown.

## Geography

qath accepts the actual origin and destination coordinates of a verified movement.

The qath API immediately converts these coordinates to **H3 resolution 5** cells. Raw latitude and longitude coordinates are not part of the stored movement record.

This allows connectors to submit standard geographic coordinates while qath maintains one consistent geographic model across Europe.

```text
latitude / longitude
        ↓
     qath API
        ↓
H3 resolution 5
        ↓
stored movement
```

The stored movement contains geographic areas rather than exact locations.

## Carrier identification

Each participating carrier receives a bearer token issued by qath.

The bearer token identifies the carrier submitting the movement. Carrier identification is resolved by qath from the token and is not included in the movement payload.

This allows qath to associate movements with the correct carrier for private reporting and analytics while keeping the movement format itself minimal.

## Time

All timestamps must be RFC 3339 timestamps in UTC and end in `Z`.

Example:

```text
2026-09-29T06:12:00Z
```

## Verification

Verification happens before submission to qath.

The source system or connector must establish that the movement actually occurred, for example from TMS execution data combined with GPS, telematics, odometer data, or another reliable source.

qath does not use a `verified` field because verification is a requirement for submitting a movement.

## API

```http
POST /movements
Authorization: Bearer <token>
Idempotency-Key: 7d89a3b4-8b1d-48b7-883c-bad7b2a80550
Content-Type: application/json
```

A movement created for the first time returns:

```http
201 Created
```
